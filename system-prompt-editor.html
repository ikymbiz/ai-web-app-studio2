System Prompt

AI の役割・制約・基本動作だけを定義します。ユーザー入力や長いスキル定義はここに埋め込まないでください。

重要: 外部ユーザーに role: system を渡させない設計にしてください。ここで編集した system prompt はサーバー側で注入します。

Principle

プロダクト全体の原則です。LLM に毎回全文を渡すのではなく、必要な compact 版のみを使います。

UX参考ペルソナ

ペルソナは「要件」ではありません。画面設計、説明粒度、UX の参考情報として扱います。

修正方針: ペルソナに引きずられて機能要件や出力内容を固定しない。
Compiled Prompt に UX参考ペルソナを含める
通常は OFF 推奨。ON の場合も「参考であり要件ではない」として挿入します。

Skill / Template

Skill は「何を実行するか」の定義です。全文を LLM に渡さず、compact instruction だけを使います。

Token Budget

Instruction・履歴・RAG・出力予約を分離し、トークン爆発を防ぎます。

Skill Definition、Guardrail policy、課金・retry・kill policy の全文は LLM に渡さない設計にしてください。

Preview / Validate

保存前に compiled prompt の概算トークンと注意点を確認します。

PAT 管理

GitHub PAT はこの HTML に保存しません。端末のフォルダで管理し、必要なときだけターミナルから読み込んでください。

推奨: gitignore 済みの .local-secrets/github_pat.txt に保存する。
mkdir -p .local-secrets
chmod 700 .local-secrets
printf '%s' 'ghp_xxxxxxxxxxxxxxxxxxxx' > .local-secrets/github_pat.txt
chmod 600 .local-secrets/github_pat.txt

export GITHUB_TOKEN="$(cat .local-secrets/github_pat.txt)"
gh auth status || true
未確認。PAT の中身は表示しません。
禁止: PAT を HTML、JSON export、localStorage、GitHub リポジトリ、Cloudflare vars に保存しないでください。

UI修正メモ

スクリーンショットの指摘を設計に反映するためのメモです。

「動かない」ボタン: 下部入力欄と競合するため廃止。チャット入力欄のメニュー内に「不具合を報告」を入れる。
推奨メニュー:
- スキルを選択
- テンプレートを選択
- 不具合を報告
- 実行履歴
- 設定
類似機能: 個別アプリ画面を増やさず、チャット内の skill / template 選択に寄せる。予約フォームはテンプレート preview 扱い。
ペルソナ: 要件ではなく、デザイン・UX・説明粒度の参考情報。機能仕様、必須項目、業務ルールは Skill / Requirements 側に置く。
