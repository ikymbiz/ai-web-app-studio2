# SYSTEM_DESIGN.md — AI Web Studio Pro システム設計

## 1. 目的
AI Web Studio Pro は、要件整理、タスク化、優先順位付け、コード生成、デバッグ、検証、タスク消込、プレビュー、ZIP出力、GitHub公開を支援するWebアプリである。

## 2. 標準生成フォルダ構造
生成するアプリは次のRoot構造を標準とする。

```text
/
├── docs/
│   ├── PRINCIPLE.md
│   ├── DEVELOPMENT_RULES.md
│   ├── SYSTEM_DESIGN.md
│   ├── FAILURE_LOG.md
│   └── HANDOVER.md
├── tasks/
│   ├── todo.md
│   └── lessons.md
├── src/
│   ├── apps/
│   └── admin/
├── config/
└── .github/
```

## 3. 各領域の役割
- docs/: AIの外部記憶・憲法。開発原則、運用規則、設計、失敗ログ、引き継ぎを保持する。
- tasks/: 実装計画、チェックリスト、レビュー結果、修正指摘から得た教訓を保持する。
- src/apps/: メインアプリケーション、コアロジック、バックエンド処理を配置する。
- src/admin/: 管理・運用ツール、ダッシュボード、フロントエンドを配置する。
- config/: 動作環境や外部連携の設定を配置する。秘密情報は保存しない。
- .github/: CI/CD、テスト、自動検証スケジュールを配置する。

## 4. AI処理の役割分担
- チャットAI: 初回要件確認、1〜3問の質問、機能要件の整理を担当する。
- コード生成AI: 選定済みタスクを実装し、複数ファイルJSONを出力する。
- デバッグAI: プレビュー画面からの修正依頼と現在ファイルを受け取り、修正コードを出力する。
- 検証AI: タスク単位と全体を確認し、verified のタスクだけ消し込む。
- 原因分析AI: バグの原因、修正案、影響範囲、承認要否を整理する。

## 5. 管理設定
管理画面では次を設定できる。
- 管理用システムプロンプト
- コード生成の原則
- 開発ルール
- システム要件
- 実装検証用プロンプト
- 管理用Skills JSON
- ユーザーSkills
- モデルリスト
- フィードバック内容
- 修正承認モード

## 6. 検証とタスク消込
タスクは実装直後に完了にしない。検証AIが実装内容と動作経路を確認し、verified、implemented、behaviorChecked、canComplete がすべて真の場合だけ消し込む。


## v20設計: プレビュー前レビュー・エージェントログ・HANDOVER

### プレビュー表示フロー
1. コード生成AIまたはデバッグAIが複数ファイルJSONを返す。
2. アプリはファイルを保存するが、iframe プレビューは更新しない。
3. 検証AIが選定タスクの実装有無と動作経路を検証する。
4. verified 条件を満たしたタスクだけを消し込む。
5. docs/HANDOVER.md を更新する。
6. プレビュー前レビューのモーダルを表示する。
7. ユーザーが「プレビューを表示」を押した場合だけ updatePreview() と preview 画面遷移を実行する。

### エージェント進行ログ
チャットと進行タブに、Planner / Coder / Debugger / Verifier / Bug Analyst / Reviewer / Handover の短い作業ログを表示する。内部思考ではなく、作業段階、対象、結果だけを表示する。

### HANDOVER 更新
ワークフロー開始、段階更新、検証、承認待ち、完了、エラー、中断、beforeunload 時に、現在のタスク状態と再開手順を docs/HANDOVER.md およびローカル保存へ反映する。

## v25設計: 要件優先順位と手書きツール表示
- 生成・修正・検証の優先順位は、チャット合意内容、仕様リスト、手書き注釈、ユーザー用指示、管理用指示、ターゲットペルソナの順とする。
- ターゲットペルソナは UI/UX・文体・導線の参考情報に限定し、チャットで決めた機能、サービス内容、画面構成、表示文言を上書きしない。
- プレビュー画面の手書きツールは常時表示せず、修正依頼欄左のメニューから必要時のみ開く。
- 手書きモード中はプレビュー上に最小限の状態バッジだけを表示し、注釈画像は修正依頼送信時に添付する。
